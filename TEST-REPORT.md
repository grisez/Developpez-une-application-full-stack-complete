## Anomalies found and fixed

Each anomaly was fixed together with a test that reproduces it, so that it cannot come back.

### 1. CSRF protection silently disabled

- **Symptom**: a state-changing request carrying a valid JWT cookie but no CSRF token was accepted.
- **Cause**: the OAuth2 resource server of Spring Security skips the CSRF check on every request carrying a bearer token. This is safe for a token sent in a header, not for a token sent automatically by the browser in a cookie.
- **Fix**: the default CSRF configuration is replaced by an explicit `CsrfFilter`, applied to every request (`SecurityConfig`).
- **Tests**: `SecurityConfigTest.stateChangingRequestWithoutCsrfTokenIsForbidden`, `TopicIntegrationTest.subscribingWithoutTheCsrfTokenIsForbidden`.

### 2. An invalid token prevented logging in and out

- **Symptom**: with an expired or invalid token cookie, login and logout answered 401, and the user could not get out of this state.
- **Cause**: the resource server tries to authenticate every request carrying a token, even on public routes.
- **Fix**: `CookieBearerTokenResolver` ignores the token cookie on `/api/auth/register`, `/api/auth/login` and `/api/auth/logout`.
- **Test**: `SecurityConfigTest.publicEndpointsIgnoreAnInvalidTokenCookieSoThatUsersAreNeverStuck`.

### 3. Profile subscriptions taken from the wrong source

- **Symptom**: the profile listed the subscriptions read from the `User` entity instead of the list prepared by the service, sorted by name and loaded in a single query.
- **Cause**: `UserMapper.toProfile` receives the entity and the list of subscriptions; both expose a `subscriptions` property, and MapStruct picked the entity's one.
- **Fix**: an explicit `@Mapping(target = "subscriptions", source = "subscriptions")` makes the parameter take precedence.
- **Tests**: `UserServiceImplTest.getProfileReturnsTheUserWithTheirSubscriptions` (real mapper), `ProfileControllerTest.getProfileReturnsTheLoggedInUserWithTheirSubscriptionsButNoPassword`.

### 4. Fields validated before being trimmed

- **Symptom**: a username such as `"  ab  "` passed the minimum length check, then was saved as `ab`, shorter than allowed.
- **Cause**: Bean Validation checked the raw value, and the spaces were removed afterwards.
- **Fix**: the request records trim their fields in their compact constructor, before validation; the front-end trims the text fields as they are typed (`appTrim` directive). The password is kept as typed.
- **Tests**: `AuthRequestsTest`, `trim.directive.spec.ts`.

## Known limits

- The end-to-end tests are not run by the CI: they need MySQL, the back-end and the front-end running together.
- The `UserNotFoundException` branches of the services are not covered: they can only happen if the account of a logged-in user is deleted, which the application does not allow yet.
